# Bez Heal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or execute task-by-task with the tests below.

**Goal:** Add a rootless, Mac-local `bez heal` command family that validates a reported HTTPS host via direct and Bez proxy paths, then keeps an expiring exact-host Xray routing override only when the evidence supports it.

**Architecture:** `bez heal` persists its state under `~/Library/Application Support/BezVPN` and materializes the active Xray config from the selected base Smart/All config plus unexpired overlays. It never writes the shared SmartDNS policy, router config, macOS DNS, `/etc/hosts`, or a suffix rule automatically. The initial evidence source is an explicit URL or HAR replay because HTTP CONNECT/Xray logs cannot reliably expose an HTTPS response status or URL.

**Tech Stack:** Generated Bash CLI in `src/macos-installer.ts`; Python 3 for JSON/HAR processing; Xray local user LaunchAgent; Node test runner through `tsx`.

## Global Constraints

- macOS rootless only; do not use `sudo`, TUN, `/etc/hosts`, or central SmartDNS writes.
- Rules are exact hostnames, HTTPS port 443, maximum 25 entries, 24-hour TTL, and require two successful proxy probes and two failed direct probes.
- Reject IP literals, local/private hostnames and addresses, URLs with credentials, and wildcard/suffix inputs.
- Store no query strings, credentials, cookies, or request bodies in the audit log.
- `heal off` removes only dynamic overlays and preserves standard `bez smart`, `bez all`, and `bez off` proxy restoration behavior.

## Acceptance

- A confirmed direct-failure/proxy-success host becomes a local exact route with expiry and an audit entry.
- A host that works direct creates no overlay.
- Expired or removed rules no longer appear in the materialized config.
- Shared SmartDNS policy and OpenWrt configuration remain unchanged by every `bez heal` command.
